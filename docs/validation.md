They do not replace visual or platform compatibility testing.

## Retained evidence

- [Runtime fingerprint](observed-runtime.json): application versions, SHA-256 hashes, symbol presence and byte offsets. Generated by `tools/inspect-runtime.py` without modifying app files.
- [Cursor metadata observations](cursor-observations.json): only the cursor windows from the original live metadata probe; unrelated window titles were omitted.
- [Live prototype trace](agent-trace.txt): cursor acquisition, movement and click-counter receipt. Positions are local desktop coordinates; no typed text or screenshots are logged by the app.
- [Native preview screenshot](native-preview.png): captured through official CUA. It shows counter value 1; the later 1-to-2 click was separately confirmed by CUA accessibility state and the trace.
- [Preset render](presets.png): generated using the same `BuddieView` code as the app. This is a renderer export, not a desktop screenshot.

## Limits of the evidence

The native preview establishes character appearance. The trace establishes adapter activity. Neither alone proves that the character perfectly covers the original pointer on every desktop surface. A screenshot of Calculator obtained through CUA still contained OpenAI's gray cursor; the independent buddy does not replace the runtime's captured cursor rendering.

The first CUA attempt to inspect the overlay-only app timed out because it did not provide a normal content window. Adding an ordinary preview window made UI inspection possible. Two initial preview actions reported that the app had changed; a fresh accessibility read followed by one click produced the verified 1-to-2 transition. Those earlier calls are not counted as successful automation checks.

Calculator's sidebar was opened and restored during the cursor experiment. No calculator values were edited. More than one cursor window was active, and the trace shows that the prototype can switch to another recently moving cursor. This is an explicit limitation of the current selection heuristic.

Screen Recording authorization was already available to the test process. A fresh application installation, permission prompts and authorization after moving/signing the app have not been tested. Sprite file validation and cropping were tested programmatically; a real user-generated pack has not been imported through the file picker yet.

Still unverified: exact hotspot calibration, complete visual coverage, physical-mouse click-through on a clean machine, CPU/battery cost, rapid-motion latency, multi-monitor/full-screen/Spaces behavior, locked/background displays, built-in browser and PiP replacement, custom animation quality, Intel, older macOS versions, Windows and Linux. No packaged binary release has been published. See Git history for source publication.
